0) 결론/결정안(1~3줄)
- 1차는 “Case Worklist/Detail 데이터 계약 확정 + 탭별 최소 API”를 만들고, 하드코딩을 제거한다.
- Tenant Scope(X-Tenant-ID) + Audit_event_log 기록(조회/상세/탭조회/링크이동을 트리거하는 API)까지 포함한다.
- 불확실한 AI 고도화(LLM RAG 성능/모델) 자체는 2차(Agentic 강화)로 두고, 1차는 “데이터 파이프+계약”을 완성한다.

Assumptions(1줄): detect 배치가 agent_case(또는 동등 테이블)에 케이스 row를 생성하며 FE는 /synapse/cases, /synapse/cases/{id}로 조회한다.
Open Questions(1줄): 현재 Case Detail 탭들의 데이터 소스(테이블/뷰)와 aura_event 스키마(스트림 payload)가 최신 소스에서 확정인지.
Default(1줄): 1차에서는 각 탭 API는 “read-only 최소 스키마”로 제공하고, 계산/추천은 P1/P2로 분리.

1) 구현 범위(In/Out)
IN (P0)
- Case Worklist API: 필터(status, severity, date range, search), paging/sort, summary(counts)
- Case Detail API: 기본 메타 + 핵심 식별자(bukrs/belnr/gjahr/buzei/sourceType/dedup_key) + evidence_json
- “관련 미결재항목” 링크가 ‘관련 필터’로 Open Items 조회되도록: /open-items?caseId= 또는 key-based filter 지원
- “데이터 계보보기(Lineage)” 페이지가 케이스 키 기반으로 조회되도록: /lineage?caseId= 또는 (bukrs/belnr/gjahr)
- Audit: VIEW_LIST/VIEW_DETAIL + 각 탭 조회도 최소 기록

IN (P1)
- Case Detail 탭 API 5종: 
  1) AI 분석(analysis summary) — 초기엔 placeholder(규칙 기반 요약)라도 실데이터 구성
  2) 에이전트 스트림 metadata (SSE는 aura, BE는 stream session 메타/lastEventId 저장)
  3) 신뢰도(score breakdown) — score 구성요소 반환
  4) 유사케이스(similar cases) — 최소: same vendor/amount range/time range 기반
  5) RAG evidence list — 초기엔 DB evidence_json을 list 형태로 정규화해 반환

IN (P2)
- 시뮬레이션 모드: “write” 없이 what-if 계산 API(POST /cases/{id}/simulation) + audit 기록
- 상태 전이/승인(HITL) API: approve/reject/execute 연계(존재 시)

OUT (이번 라운드)
- LLM 기반 자동분석/자동조치 실행(무승인) / 실시간 SAP JCo 연동(배치 우선) fileciteturn28file0

2) API 스펙(초안, OpenAPI 스니펫 + 예시)
※ 실제 소스의 기존 엔드포인트가 다르면 “기존 유지” 우선. 아래는 최소 계약 템플릿.

3) DB 매핑(테이블/컬럼/조인키 + 인덱스/제약)
- agent_case (또는 동일): case_id(PK), tenant_id, status, severity, score, source_type, bukrs, belnr, gjahr, buzei, dedup_key(UNIQUE), detected_at, updated_at, evidence_json, last_detect_run_id
- open_items: (tenant_id, bukrs, belnr, gjahr, buzei?) 또는 case_id FK(있다면)
  - 없다면: Case keys로 open_items를 조회하도록 인덱스 필요: (tenant_id,bukrs,belnr,gjahr)
- lineage tables: fi_doc_header/fi_doc_item 등의 키 기준 조회
- audit_event_log: VIEW_LIST/VIEW_DETAIL 등

인덱스(필수):
- agent_case: (tenant_id, detected_at desc), (tenant_id, status), (tenant_id, severity), UNIQUE(tenant_id, dedup_key)
- open_items: (tenant_id, bukrs, belnr, gjahr)

4) 백엔드 작업(컨트롤러/서비스/리포지토리/검증/페이징/정렬/권한/테넌트)
